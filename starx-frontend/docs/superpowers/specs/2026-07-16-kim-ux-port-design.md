# Kim 分支 UX 移植设计

## 背景

`Kim` 分支包含多处前端布局、视觉层级和加载动画优化，但其业务逻辑落后于当前 `develop`。直接合并会覆盖或削弱 `develop` 已具备的任务恢复、异步轮询、发布状态、错误恢复和内容持久化能力，并在多个核心文件产生冲突。

本次改造以 `develop` 为唯一业务逻辑基线，手工移植 `Kim` 的布局与 UX。账号报告页面明确排除在移植范围之外。

## 目标

1. 将 `Kim` 的页面布局、视觉样式、交互反馈和加载动画移植到 `develop`。
2. 保留 `develop` 的全部业务功能、状态管理、API 调用和错误处理。
3. 当 `Kim` 的布局没有容纳 `develop` 的新功能时，保留功能入口，并用同一视觉语言重新安置。
4. 消除只依赖旧 JSX 或 CSS 字符串形态的脆弱测试，同时继续验证关键业务能力。
5. 确保账号报告页面及其专属样式不受本次改造影响。
6. 采用 `Kim` 的发布路径：内容先保存到流程管理，再从任务详情抽屉发布。
7. 内容创作采用 `Kim` 的分步向导，而不是 `develop` 的单屏工作台。

## 非目标

- 不采用 `Kim` 的旧任务轮询、保存、发布或恢复逻辑。
- 不重写既有发布服务；仅扩展流程管理发布所需的状态校验、可见性约束和独立重试尝试契约。
- 不修改账号报告页面的组件结构和专属样式。
- 不直接以 `Kim` 的 `ContentCreation`、`useStarxApp` 或其他核心文件覆盖 `develop`。
- 不引入与 UX 移植无关的功能或重构。

## 总体方案

采用“以 `develop` 为底逐页手工移植视觉层”的方式。

- 页面组件继续持有业务状态并调用现有业务函数。
- 新增或移植的视觉组件仅接收展示数据和事件回调，不发起 API 请求，不拥有任务轮询，不自行持久化业务状态。
- 对 `Kim` 中同时包含视觉与旧逻辑的组件，只提取视觉结构；不直接复用其业务实现。
- CSS 使用页面或组件命名空间，避免全局选择器污染账号报告等未纳入范围的页面。
- 每个页面以独立测试循环完成，降低大范围样式回归风险。

## 组件边界

### 展示组件

下列组件只负责展示：

- `LoadingOverlay`：展示主消息、辅助消息、进度、环形动画和粒子效果。
- `StepWizard`：展示步骤、当前步骤和已完成步骤，并通过回调通知页面。
- 流程矩阵：展示按阶段分组的任务和选择状态。
- 流程详情抽屉：展示任务信息，并向页面回传推进、编辑、发布和关闭事件。
- 流程发布弹窗：展示已保存的发布素材、文案、设备状态、可见性、相册选项、发布进度和失败恢复操作。
- 标签选择、已选标签摘要等辅助视觉组件：只接收列表、选中状态和回调。

展示组件不得直接依赖 API 客户端，也不得复制 `useStarxApp` 的领域逻辑。

### 页面组件

页面组件继续负责：

- 数据读取与归一化。
- 任务创建、刷新、恢复和轮询。
- 表单校验、保存和发布。
- 加载、成功、失败和重试状态。
- 路由或页面切换。
- 将真实业务状态映射为展示组件属性。

## 逐页设计

### 内容创作

- 保留 `develop` 当前的图片提示词计划、视频脚本包、素材恢复、生图任务、视频分析、脚本改写、发布状态和错误恢复逻辑。
- 移植 `Kim` 的科技感加载层、步骤导航、参考素材入口、分步信息层级和结果区视觉。
- 不直接使用 `Kim` 的 `ImageWizard` 或 `VideoWizard` 业务实现；需要时提取无状态展示片段。
- 保留普通图文、链接图文、视频创作、最近任务、反推历史和图片大图预览等 `develop` 功能。
- 内容创作页移除直接发布入口；保存到流程时持久化发布文案、目标平台和可发布媒体候选，供流程管理发布弹窗恢复。
- 图文固定为三步：第一步“素材参考”容纳上传、链接解析、提取历史和反推入口；第二步“风格选择”容纳标签和图片提示词计划偏好；第三步“提示词与生成结果”容纳提示词编辑、素材图、生图任务、结果、最近任务、反推历史、预览和保存到流程。
- 视频固定为两步：第一步“素材参考”容纳链接解析、视频分析和分析历史；第二步“脚本创作”容纳脚本包、改写、发布文案和保存到流程。
- 当前步骤与已完成步骤写入 `creationState`，刷新或重新打开任务时恢复；业务任务状态仍由 `develop` 的真实任务记录决定。
- 对 `Kim` 未预留的位置，使用其卡片、按钮、步骤区和状态条视觉重新安置现有入口。

### 流程管理

- 使用 `Kim` 的阶段矩阵和右侧详情抽屉视觉结构。
- 阶段矩阵严格采用 `Kim` 的“固定任务信息列 + 每任务一行 + 阶段列”结构；本项目保留七个真实阶段（含拍摄），而不是改成按阶段分栏的看板。
- 保留 `develop` 的搜索、负责人筛选、阶段分页、任务选择、阶段推进和编辑逻辑。
- 任务详情抽屉是唯一发布入口。打开发布弹窗时读取任务关联的已保存创作，默认选中创作阶段保存的媒体和发布文案，并允许用户在确认前调整。
- 发布入口只对原始 `status` 字段严格等于 `pending_review` 且存在关联创作的任务开放；用于矩阵展示和筛选的状态别名归一化不得参与发布授权，`pending`、`pending_publish` 等旧别名都不能发布。
- 发布请求、设备校验、状态轮询、时间线、失败重试和设备配置入口沿用 `develop` 的行为。
- 后端在创建发布尝试前重新读取关联任务，并同样要求其原始 `status` 严格等于 `pending_review`；缺少关联任务、账号不一致、创作关联不一致或任务不在待发布阶段时返回冲突错误。前端校验只用于即时反馈，不能替代服务端约束。
- 可见性严格使用 `0=公开`、`1=好友`、`2=仅自己`，前后端都拒绝其他值。
- 发布文案为必填项；去除首尾空白后为空时，前端禁止确认并显示提示，后端也拒绝请求，不得静默回填创作旧正文。
- 首次发布沿用既有外部任务 ID；只有上一次发布为失败或取消且用户明确重试时，后端创建递增的独立发布尝试 ID，并保留历史尝试。进行中或已成功的发布不得重复提交。
- 发布调用只有在能够确认请求发送前失败，或外部服务给出明确拒绝时，才把当前尝试写为 `failed`。读取失败、写入失败、外部 5xx、409 后状态恢复失败，以及缺少或不匹配 `external_id` / `status` 的畸形 2xx 都属于“不确定提交”：保留同一个 `attempt` 与外部任务 ID，维持可轮询的提交中投影，不开放重试，也不得创建新尝试。
- `000022_creation_publish_attempts` 降级前必须把每条创作的最新发布投影和按时间排序的最后 50 条尝试历史物化回旧的 `content_creations.creation_state`；写回时保留 `creation_state` 的其他业务键，再删除独立尝试表，避免降级后丢失发布状态或把旧尝试误判为可重试。
- 发布状态按 `creationId` 隔离，发布一个历史任务不得覆盖当前内存中另一条创作内容。
- 所有操作继续通过页面传入的回调执行。
- 抽屉应避开顶部栏，并在窄屏下回落为可用布局。

### 竞品监控

- 保留 `develop` 的真实监控 Hook、账号与视频数据、刷新状态汇总、单项刷新、批量刷新和新增目标逻辑。
- 精确移植 `Kim` 的同栏顶部操作区、模式切换、三/二/一列响应式卡片、方形缩略块、指标胶囊、按钮层级和空状态视觉。
- 页面专属样式收敛到 `competitor-monitor.css`；中等宽度允许把扩展操作换到标题下方，防止真实账号名和批量刷新互相挤压。添加弹窗必须限制键盘焦点，并在关闭后恢复到原触发按钮。
- 不引入 `Kim` 分支中的模拟数据或旧请求路径。

### 选题中心

- 保留 `develop` 的筛选、推荐信息归一化、偏好弹窗和创作任务交接逻辑。
- 移植 `Kim` 的筛选条、推荐标识、平台信息、卡片层级和创建过程反馈。
- 页面专属响应式样式收敛到 `topic-center.css`；偏好确认后的生成遮罩与偏好弹窗不得同时暴露为两个活动模态层。
- 无真实推荐分值时使用同一金色位置显示“AI 推荐”，不得根据 ID 生成伪星级；创作统计只读取当前账号的真实仪表盘数据，不使用固定兜底值。
- 创建按钮的禁用、加载和失败状态继续由真实任务状态驱动。

### 账号资料与知识库

- 移植 `Kim` 的账号卡片、筛选区、表单区、发布设备配置和知识库弹窗视觉。
- 保留 `develop` 的分页、搜索、多平台链接、删除确认、知识库选择和表单校验。
- 点击“管理知识库”后先进入 `Kim` 的知识库管理列表，再进入两步新建或编辑器：第一步维护名称、产品名称、所属行业、官网和产品介绍，第二步维护品牌故事、价格、Logo、图片素材、联系方式以及字段启用开关。列表必须连接 `develop` 的真实分页、关键字搜索、编辑和删除回调。
- `KnowledgeBaseModal` 只负责管理/编辑模式、焦点和忙碌态关闭锁；`KnowledgeBaseManager` 负责真实列表、搜索、分页、编辑和二次确认删除；`KnowledgeBaseEditor` 负责两步表单、字段开关、素材数组、归一化以及创建/更新回调。
- `industry` 是真实知识库领域字段，而不是仅供界面显示的临时值：前端编辑器、表单归一化和 API 请求必须携带它，后端请求/响应 Schema、领域模型、数据库列、创建与更新服务都必须持久化并回传它，创建后重新读取与编辑后重新读取均保持原值。
- 知识库创建、编辑、删除和素材字段继续使用真实业务实现；删除前二次确认，保存和删除期间锁定重复提交，忙碌时禁止通过关闭按钮、遮罩或 Escape 退出。
- 弹窗进入时聚焦首个可操作控件，Tab / Shift+Tab 必须在对话框内闭环，关闭后恢复原触发按钮；旋转加载和过渡效果在 `prefers-reduced-motion: reduce` 下停止或降级。
- 不显示并不存在的“已保存草稿”，不保留无行为的展开按钮或账号卡片省略号；账号编辑、删除和切换必须是可执行操作。
- 账号与知识库样式分别收敛到页面命名空间文件，禁止复制 `Kim` 的账号报告样式。

### 工具箱

- 由 `Toolbox.jsx` 持有全部可编辑状态和现有处理函数，并拆分为 `ToolboxNav`、`AiImageWorkspace`、`ScriptRewriteWorkspace`、`ProhibitedWordWorkspace` 四个展示组件；展示组件只接收值和回调。
- 强参考 `Kim` 的左侧工具导航、三栏生图工作区、卡片式结果区和操作按钮层级，但只保留 `develop` 已有的“AI对话生图”“脚本改写”“违禁词检测”三项工具，不引入 `Kim` 的一键解析、转写、封面制作、模拟图片或假网络素材。
- 三个工作区的输入状态提升到 `Toolbox.jsx`，切换工具标签时不得丢失对话、视频链接、改写要求、待检测文案或检测结果。
- 导航暴露稳定的“工具箱导航”名称并标记当前项，输入框和文本域提供可访问名称；结果变化通过合适的实时区域反馈。
- 工具箱视觉样式独立收敛到 `styles/toolbox.css` 的 `.toolbox-ux-shell` 命名空间，保持桌面三栏、中等宽度重排和窄屏单列，并在减少动态偏好下停用非必要过渡。
- 不在本次工作中扩展工具箱业务能力。

### 公共布局

- 移植必要的顶部间距、页面容器、弹窗层级和响应式规则。
- 新增样式必须限定在对应页面或组件命名空间中。
- 不修改账号报告组件；不得新增会改变账号报告布局的宽泛选择器。

### 账号报告

- 不移植 `Kim` 的账号报告 JSX。
- 不移植 `Kim` 的账号报告专属样式。
- 公共样式修改需要通过现有账号报告测试或静态保护断言，证明其结构未被覆盖。

## 数据流

1. 页面从 `app`、页面 Hook 或现有工具函数读取真实状态；流程发布会按任务的 `creationId` 读取已保存创作。
2. 页面将状态转换为展示属性，例如当前步骤、加载文案、任务状态和按钮可用性。
3. 展示组件渲染布局，并通过回调上报用户操作。
4. 页面调用 `develop` 现有业务函数执行操作。
5. API 结果进入现有状态管理，再驱动展示组件更新。

内容创作步骤条是受控展示：页面根据持久化步骤和真实任务结果更新 `currentStep`、`completedSteps`，步骤组件只负责显示和回传点击。未完成的后续步骤不可直接跳转，已完成步骤可返回编辑。

发布数据流固定为：内容创作保存发布素材与文案 → 流程管理选择任务 → 加载关联创作 → 发布弹窗确认素材、文案和设备 → 前后端共同确认任务原始状态仍严格等于 `pending_review` → 预留当前发布尝试与外部任务 ID → 提交外部发布 → 以 `creationId` 记录并轮询当前发布尝试状态。只有可信的失败或取消终态允许显式重试并创建新的后端尝试；不确定提交继续恢复和轮询原尝试。

加载动画不得通过模拟结果推进业务状态。没有真实进度时，可在视觉层展示不超过 90% 的缓动进度；业务完成或失败仍以真实状态为准。

## 错误与恢复

- 保留 `develop` 的错误消息、重试入口和轮询失败阈值。
- 加载层必须在成功、失败、取消或组件卸载时清理计时器。
- 发布、生图、脚本改写和视频分析的失败状态不得被纯动画遮蔽。
- 流程发布失败后保留弹窗输入和所选媒体，并提供重新发布与设备配置入口。
- 发布重试只从可信发布状态推导；前端不得由用户输入直接指定重试，后端不得复用失败尝试的外部任务 ID。
- 不确定提交不得伪装成失败：读取/写入异常、5xx、409 状态恢复失败或畸形 2xx 后继续保留预留记录、同一尝试编号和同一外部任务 ID，直到状态查询得到权威终态或租约恢复流程确认结果。
- 用户清空发布文案时保留当前编辑状态并提示必填，不得让界面显示空文案而实际发布旧正文。
- 设备配置错误从当前尝试及历史尝试中识别；普通素材、文案或内容错误不得误导用户进入设备配置。
- 页面刷新或重新打开任务后，继续使用 `develop` 的持久化状态恢复素材、任务和草稿。
- 展示组件中的事件不得绕过现有校验或直接构造请求。

## 样式策略

- 优先使用组件级或页面级前缀，例如 `creation-`、`workflow-`、`competitor-`、`topic-`、`account-` 和 `tool-`。
- 避免修改裸元素选择器和过于宽泛的 `.card`、`.modal`、`.page-section` 规则；如必须扩展，应增加页面祖先选择器。
- 从 `Kim` 移植的样式只保留实际使用部分，避免整文件复制未使用规则。
- 动画尊重 `prefers-reduced-motion`，减少动态偏好下关闭粒子位移和连续旋转。
- 保持桌面端信息密度，并为窄屏提供单列或可滚动回退。

## 测试策略

### 测试先行

每个页面先增加会失败的 UX 结构测试，再移植最小视觉实现使其通过。

### 业务回归

- 保留现有业务契约测试，确保任务恢复、脚本轮询、生图任务、发布状态、素材持久化和流程推进仍存在。
- 只调整依赖旧 JSX 排版、空格或单一文件位置的断言。
- 当视觉结构被提取到展示组件时，测试应同时验证页面引用该组件以及组件提供所需结构。

### 视觉契约

至少覆盖：

- 加载动画的消息、进度和计时器清理。
- 内容创作步骤导航与关键 `develop` 功能入口共存。
- 图文三步和视频两步在刷新、任务恢复和异步任务完成后保持正确步骤。
- 流程矩阵、详情抽屉及页面回调连接。
- 非待发布任务不显示可执行的发布操作，待发布任务可以打开发布弹窗。
- 内容创作不再直接发布，保存结果包含流程发布所需媒体和文案。
- 流程发布弹窗恢复已保存创作、调用现有发布 API，并按 `creationId` 轮询状态。
- 服务端拒绝非待发布任务、无关联任务、空发布文案、非法可见性和重复发布；失败或取消后的显式重试生成递增尝试 ID 并保留历史。

## 验收标准

1. 纳入范围的页面采用统一的 `Kim` 视觉语言和加载反馈。
2. `develop` 的全部现有功能入口仍可访问。
3. 任务恢复、轮询、保存、发布和错误恢复逻辑保持 `develop` 行为。
4. 发布入口统一位于流程管理任务详情，内容创作页不再直接发布。
5. 内容创作使用图文三步、视频两步的 `Kim` 向导，并保留全部 `develop` 功能。
6. 只有原始状态严格等于 `pending_review` 的任务可以进入发布弹窗，旧状态别名不得获得发布权限。
7. 后端同样强制原始 `pending_review` 状态和非空发布文案；发布可见性映射正确，可信失败或取消重试使用独立尝试 ID 并保留历史，不确定提交保持原尝试且不开放重试。
8. 账号报告组件与专属样式没有被修改。
9. 所有前端测试、后端发布契约测试和生产构建通过。
10. 无未使用的大段 `Kim` 旧业务组件或重复状态管理代码。
11. 动画在减少动态偏好下可安全降级。
12. 知识库 `industry` 能完成创建、读取、更新和再次读取的端到端持久化。
13. `000022` 降级不会清空旧 `creation_state` 的其他键，并能保留最新发布投影及最后 50 条尝试历史。
