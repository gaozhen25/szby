# 内容创作界面 Kim 精确对齐设计

## 背景

现有 `develop` 已保留完整的异步生图、视频分析、脚本包、任务恢复、素材持久化和流程交接能力，但内容创作页只采用了 Kim 的视觉语言，没有复刻 Kim 的页面结构和逐步交互。默认图文首屏仍是双栏工作台，步骤条、链接流程、结果区、视频脚本区和保存入口也与 Kim 明显不同。

本次改造将验收标准从“强参考 Kim”提升为“内容创作界面与 `origin/Kim` 完全一致”。业务数据和结果可因账号与任务不同而变化，但同一状态下的页面结构、文案、顺序、尺寸、间距、颜色、响应式和交互反馈必须与 Kim 对齐。

## 产品决策

采用“Kim 精确展示层 + develop 业务控制器 + 渐进披露额外能力”。

比较过的方案：

1. 直接以 Kim 的 `ContentCreation.jsx` 覆盖 `develop`。视觉收敛最快，但会带回旧轮询、假图片、旧保存与旧状态恢复逻辑，不能接受。
2. 复刻 Kim 的 DOM、CSS、文案和状态切换，把 `develop` 的真实状态与回调接入展示层。能同时满足视觉精确度和业务完整性，采用此方案。
3. 仅在现有工作台上补 CSS。无法修正步骤、信息层级和交互结构，不满足“完全一致”。

当 Kim 没有容纳 `develop` 新功能的位置时，遵循以下优先级：

1. 不改变 Kim 主流程的常驻结构。
2. 与当前步骤直接相关的能力进入 Kim 原有结果页或卡片动作区。
3. 高级设置、历史记录和恢复工具进入二级弹窗或抽屉。
4. 已在其他页面存在的能力不在内容创作页重复常驻，例如发布设备状态由账号档案或流程发布界面负责。

## 精确一致的定义

### 必须一致

- 页面标题、账号名称位置、账号类型信息和创作平台位置。
- 图文/视频切换按钮的顺序、文案、图标和选中态。
- 步骤条的节点布局、连线、当前节点信息、完成态和可返回规则。
- 图文普通流程的三个步骤：素材参考、风格选择、提示词输入。
- 图文链接流程的三个步骤：链接解析、提示词反推、生成图片。
- 视频流程的两个步骤：素材参考、脚本创作。
- 每一步中的标题、说明、表单顺序、按钮文案、空状态、加载状态、成功状态和失败状态位置。
- 保存到流程管理入口及交接弹窗的结构。
- 桌面、中等宽度和窄屏的响应式折行与单列规则。
- Kim 使用的背景、边框、阴影、颜色、字体层级、间距、圆角和动画节奏。

### 允许不同

- 账号名称、账号类型、平台列表、解析结果、标签、提示词、任务状态、生成图片等真实动态数据。
- 为可访问性增加但不改变视觉的语义标签、键盘焦点、进度语义和减少动态支持。
- Kim 中的假图片、假选题素材和本地模拟结果必须由 `develop` 的真实数据、真实空状态或真实任务状态替代。
- 服务端错误文案可使用 `develop` 返回的具体错误，但错误容器的位置和视觉必须与 Kim 同类状态一致。

## 范围

仅改造内容创作页及其专属展示组件和专属样式。流程管理仍是唯一发布入口；账号报告继续保持完全不变。

包含：

- 内容创作页顶栏、类型切换和平台切换。
- Kim 步骤条。
- 图文普通流程、图文链接流程、视频流程。
- Kim 加载遮罩、解析结果页、标签选择、提示词与结果区。
- 保存到流程管理弹窗。
- 与上述页面直接相关的测试和样式。

不包含：

- 修改发布业务规则。
- 修改后端接口。
- 引入 Kim 的假图片、假统计或旧 API 调用。
- 修改账号报告、流程管理、账号档案、选题中心、竞品监控或工具箱。

## 架构

### 页面控制器

`ContentCreation.jsx` 继续拥有真实业务状态与副作用：

- 创作记录读取与恢复。
- 图文链接解析和反推任务。
- 图片提示词计划、生图任务和轮询。
- 视频分析、视频脚本包生成、改写和轮询。
- 素材保存、创作草稿持久化和流程交接。
- 错误、重试、卸载清理和任务归属校验。

页面控制器不再直接拼装大段页面布局，而是把归一化状态和回调传入 Kim 展示组件。

### Kim 展示层

新增 `src/components/creation/kim/`，按用户可感知的流程拆分：

- `KimCreationHeader.jsx`：标题、账号信息、平台与创作类型切换。
- `KimStepWizard.jsx`：精确复刻 Kim 步骤条，同时保留按钮语义与键盘访问。
- `KimImageReferenceStep.jsx`：上传卡、链接卡、跳过卡。
- `KimImageLinkPromptStep.jsx`：逐图提示词反推表。
- `KimImageLinkResultStep.jsx`：逐图生成结果表。
- `KimImagePromptStep.jsx`：普通图文提示词、素材、参数和结果。
- `KimVideoReferenceStep.jsx`：视频链接解析与跳过入口。
- `KimVideoScriptStep.jsx`：原版脚本、AI 改写脚本和发布信息。
- `KimWorkflowSaveModal.jsx`：Kim 交接弹窗。
- `KimCreationExtrasDrawer.jsx`：仅承载 `develop` 独有的历史、偏好、模板和恢复工具；默认关闭，不影响主流程几何。

每个展示组件只接收值、状态和事件回调，不直接调用 API，不创建轮询，不持久化业务状态。

### 样式

新增 `src/styles/content-creation-kim-exact.css`，以 Kim 分支相关 CSS 为权威来源，并保持相同类名、选择器层级和媒体查询。页面使用 `.creation-page` 与 `.kim-creation-*` 命名空间限制影响范围。

移除或停止使用当前 `.creation-ux-shell`、`.creation-wizard-card`、`.creation-step-grid` 等会改变 Kim 几何结构的内容创作专属布局规则。不得增加影响账号报告的裸元素或宽泛 `.card`、`.modal` 规则。

## 用户流程

### 图文普通流程

1. 首屏展示 Kim 的“选择你的创作起点”：上传参考图、粘贴内容链接、无素材直接开始。
2. 上传图片可触发真实反推；链接使用真实解析；跳过直接进入标签选择。
3. 标签页完全采用 Kim 的分类卡、已选标签和下一步操作。
4. 提示词页采用 Kim 的提示词、负向提示词、比例、创意程度、素材图、生成数量和结果区。
5. 图片提示词计划继续在后台提供真实多卡生成能力；其高级编辑器从二级抽屉进入，默认不改变 Kim 提示词页。

### 图文链接流程

1. 链接解析成功后进入 Kim 解析结果页。
2. 继续创作进入“提示词反推”逐图表格，每张真实解析图片拥有独立提示词。
3. 下一步进入“生成图片”逐图表格，沿用 `develop` 的真实任务和变体选择。
4. 生成失败、进行中和完成都在 Kim 表格对应行内展示，不伪造结果。

### 视频流程

1. 首步采用 Kim 的视频链接输入、开始解析和跳过入口。
2. 解析成功后采用 Kim 解析结果页，再进入脚本创作。
3. 脚本页主界面固定为 Kim 的原版脚本与 AI 改写脚本双栏，标题、标签和发布文案位于下方。
4. `develop` 的分镜、导演字段、BGM、节奏和高级偏好进入二级抽屉；生成失败或追踪错误在脚本页顶部使用 Kim 状态容器呈现。

### 保存到流程

- 页面底部保留 Kim 的“保存到流程管理”入口。
- 打开后使用 Kim 的交接弹窗填写负责人、截止日期、优先级、初始阶段和交接备注。
- 真实媒体、发布文案、平台和 `develop` 创作状态继续持久化。
- 内容创作页不重新引入直接发布按钮。

## 状态与数据流

1. `ContentCreation.jsx` 从 `app` 读取当前账号、创作记录、解析记录和生成任务。
2. 控制器将数据归一化为 Kim 展示层所需的 view model。
3. 展示层只回传上传、解析、跳过、下一步、返回、生成、重试、保存和打开高级工具等事件。
4. 控制器调用现有 `develop` 业务函数，并把结果写回现有持久化状态。
5. 当前步骤和完成步骤按图文普通、图文链接、视频三个流程分别恢复，切换创作类型不得串用步骤状态。

业务完成只由真实任务终态驱动。无真实百分比时，Kim 加载动画可缓动到 90%，但不得触发步骤完成或生成模拟结果。

## 错误与恢复

- 上传格式、大小和数量沿用 `develop` 校验，提示位置使用 Kim 卡片内状态区。
- 解析、反推、生图、视频分析和脚本包失败必须保留用户输入并提供明确重试。
- 连续追踪失败达到既有限制后停止静默轮询，展示恢复入口。
- 切换账号、切换创作或卸载页面后，旧请求不得写入新任务。
- 高级抽屉关闭不得清空编辑状态。
- 保存到流程失败时保持交接弹窗及用户填写内容。

## 测试策略

### 契约测试

- 对 Kim 标题、步骤文案、主容器类名、卡片顺序、按钮文案和默认隐藏区域建立源码契约。
- 对三个流程的步骤恢复和跳转规则建立行为测试。
- 验证主页面不存在当前双栏工作台、常驻历史栏、常驻设备提示和直接发布入口。
- 验证 `develop` 业务回调仍被真实操作触发，假图片和假结果不会进入生产代码。

### 视觉验证

- 同时运行 `origin/Kim` 与实现分支。
- 使用同一浏览器、同一视口、同一创作类型和同一流程状态逐屏截图。
- 对 1440×900、1024×768、390×844 三种视口检查布局。
- 覆盖图文普通三个步骤、图文链接三个步骤、视频两个步骤、解析结果、加载遮罩和保存弹窗。
- 动态数据不同不算视觉失败；结构、文案、顺序、几何和样式不同算失败。

### 回归验证

- 内容创作定向测试全部通过。
- 前端全量测试全部通过。
- 生产构建成功。
- `git diff --check` 通过。
- 账号报告与本次改造前基线保持零差异。

## 验收清单

1. 默认图文首屏与 Kim 同版，不再出现 `develop` 双栏工作台。
2. 图文普通、图文链接和视频所有主步骤与 Kim 的结构、文案和交互一致。
3. `develop` 的真实生图、视频分析、脚本生成、恢复和流程交接功能仍可达且测试覆盖。
4. 高级能力默认隐藏，不改变 Kim 主流程的常驻几何。
5. 不包含 Kim 假素材、假任务或旧 API。
6. 浏览器逐屏对照、全量测试、构建和账号报告隔离检查全部通过。
