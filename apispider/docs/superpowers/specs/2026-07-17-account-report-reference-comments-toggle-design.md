# 账号报告参考评论开关设计

## 背景

当前账号报告生成接口没有请求参数，工作流直接继承全局 MediaSpider 评论配置。全局配置开启评论采集时，账号主页采集和行业关键词采集都会抓取评论，并把精选评论证据交给 AI 用于生成用户画像、内容策略等结论。

本次增加“参考内容评论”开关。默认关闭时，账号报告不得抓取内容评论，也不得把评论证据交给 AI；用户明确开启后，才沿用现有评论采集和聚合分析能力。

## 目标

- 账号报告页面提供“参考内容评论”开关，默认关闭。
- 同一账号页面会话内保留用户当前选择；页面刷新或切换账号后恢复关闭。
- 后端请求缺少该参数时默认关闭，兼容旧客户端和账号创建后的自动报告任务。
- 关闭时，当前账号主页采集与行业关键词采集都不请求评论。
- 关闭时，发送给 AI 的证据不包含评论。
- 开启时保持现有评论抓取、脱敏、聚合分析和禁止逐字引用规则。

## 非目标

- 不把开关保存为账号长期偏好。
- 不修改全局 MediaSpider 评论配置，也不影响竞品监控或其他爬取业务。
- 不调整评论数量、子评论数量或并发上限。
- 不迁移历史账号报告，也不在报告结果中新增评论字段。
- 不允许在任务执行过程中修改已经创建的任务参数。

## 方案选择

采用“请求参数加 workflow 持久化”方案。前端在创建报告任务时发送 `referenceComments`，后端把它保存到 workflow 的 `inputPayload`，工作流执行时从持久化输入读取本次任务的不可变选择。

没有采用仅前端控制方案，因为后端无法据此可靠跳过评论采集。没有采用账号长期配置方案，因为它会跨页面刷新保留状态，与本次确认的交互规则冲突。

## 前端设计

账号报告页面在生成操作附近展示“参考内容评论”开关，并用简短辅助文案说明：开启后会额外采集公开评论用于聚合分析，生成耗时可能增加。

页面组件以布尔状态保存选择，初始值为 `false`。生成完成后不重置，因此同一账号页面会话内连续重新生成会沿用当前选择。监听当前账号 ID；ID 变化时将选择重置为 `false`。浏览器刷新后组件重新挂载，也自然恢复 `false`。

点击“生成账号报告”或“重新生成”时，都调用 `refreshAccountReport(referenceComments)`。刷新协调器把该值原样传给前端 API，API 请求体固定为：

```json
{
  "referenceComments": false
}
```

生成期间沿用现有禁用逻辑，避免同一页面重复提交。

## 后端 API 与任务输入设计

新增账号报告任务请求模型，字段定义为严格布尔值：

```python
class CreateAccountReportWorkflowRequest(BaseModel):
    referenceComments: bool = False
```

接口接收请求体并把值传给 `WorkflowService.create_account_report_job`。服务在创建新任务时将选择写入：

```json
{
  "accountId": "账号 ID",
  "platforms": ["平台"],
  "referenceComments": false
}
```

账号创建后自动提交报告任务时不显式传参，由服务方法默认值 `False` 保证后端默认关闭。旧客户端发送空对象时也由请求模型默认关闭。

若账号已有 `pending` 或 `running` 状态的账号报告任务，后端继续复用已有任务及其原始 `inputPayload`，不会用新请求覆盖执行中的参数。

## 工作流与爬虫设计

`WorkflowStore.account_report_context` 从 workflow 的 `input_payload` 读取 `referenceComments`。只有值明确等于布尔值 `True` 时才返回开启，其余缺失或异常历史值统一按关闭处理。

账号报告专用运行参数函数新增本次任务的开关输入，并在全局参数副本上覆盖：

```python
options["enable_comments"] = reference_comments
options["enable_sub_comments"] = (
    reference_comments and bool(options.get("enable_sub_comments"))
)
```

因此关闭时，账号主页采集和行业关键词采集都会向 MediaSpider 传入 `enable_comments=False` 与 `enable_sub_comments=False`。全局配置保持不变，其他业务不受影响。

开启时，主评论采集开启；子评论仍受现有全局子评论配置约束，不会因为本开关绕过全局限制。

## AI 证据隔离

关闭时，爬虫结果正常情况下不会含评论。为避免测试桩、兼容数据或未来调用变更意外携带评论，工作流在构造报告证据前还会清空本次采集结果的评论集合与评论计数，再调用现有证据构建器。

这样形成两层保障：

1. 采集层不请求评论，减少平台压力、执行耗时和内存占用。
2. AI 边界层不接受评论，即使上游意外返回评论也不会进入提示词。

开启时继续使用现有 `build_ai_evidence` 脱敏投影。现有提示词中“仅聚合评论趋势、不得逐字引用或输出评论者身份”的约束保持不变。

## 进度与错误处理

关闭评论后，采集进度中的评论数量保持为 `0`。现有进度结构和平台失败处理不变，不新增独立评论阶段，也不显示误导性的“正在抓取评论”状态。

参数校验失败由 FastAPI 返回标准 422 响应。任务创建、调度失败和平台采集失败继续沿用现有安全错误处理，不记录评论原文或完整提示词。

## 测试设计

前端测试覆盖：

- 开关初始关闭，具有可访问的标签与状态。
- 两个生成入口都传入当前 `referenceComments`。
- API 把选择写入请求体。
- 刷新协调器把选择传递到创建任务调用。
- 生成完成后不自动重置。
- 当前账号 ID 变化时重置为关闭。

后端测试覆盖：

- 空请求体和服务方法缺省参数都把 `referenceComments=False` 写入新任务。
- 显式开启时写入 `referenceComments=True`。
- 复用活跃任务时不覆盖原有选择。
- 账号报告上下文只接受严格布尔值 `True` 为开启。
- 评论关闭时，所有平台运行参数都强制关闭主评论和子评论。
- 评论开启时，主评论开启且子评论继续服从全局配置。
- 评论关闭时，即使爬虫测试桩返回评论，AI prompt 也不含评论证据。
- 评论开启时保留现有评论证据聚合行为。

后端测试必须使用名为 `starx` 的 conda 环境运行。最后执行账号报告 API、工作流、证据和爬虫参数相关回归，以及前端 API、刷新协调器和账号报告页面相关测试。

## 验收标准

- 用户首次进入账号报告页面时，开关为关闭。
- 用户开启后生成一次报告，生成完成后开关仍开启；切换账号或刷新页面后关闭。
- 未传 `referenceComments` 的所有后端调用都默认关闭。
- 关闭时，主页与关键词采集均不调用评论抓取，评论进度为零。
- 关闭时，AI 输入不含当前账号或行业评论证据。
- 开启时，现有评论参考能力正常工作。
- 其他 MediaSpider 调用方的评论行为不发生改变。
