# 账号报告采集语义与 AI 证据分流设计

## 1. 背景与问题

账号报告工作流先采集当前账号主页公开信息，再按 AI 规划的关键词采集行业公开内容，最后将采集结果归一化后交给 AI 生成完整报告。

当前实现存在两类问题：

1. 账号报告页面会直接展示通用爬虫事件中的“博主”文案，导致“采集自己的账号主页公开信息”被用户理解成“爬取其他博主”。
2. 当前账号主页结果与行业关键词结果被追加到同一个 `crawl_results` 列表。证据归一化后，两类作品共同进入 `hot_contents`，AI 输入没有清晰表达“当前账号证据”和“行业对标证据”的用途差异。当前账号作品因此可能成为行业热门内容候选。

同时，账号报告 AI 上下文还包含内部账号 ID、用户 ID、联系方式及多个素材 URL。这些字段不是策略分析的必要输入，应从该工作流的 AI 边界中移除。

## 2. 目标

本次修改必须实现：

1. 账号报告首阶段统一表达为采集“当前账号主页公开信息”，不再把当前账号称为“博主”。
2. 行业关键词阶段与当前账号阶段使用不同的公开语义。
3. 当前账号证据和行业对标证据在采集、归一化及 AI prompt 中保持明确分流。
4. 行业热门内容、相似账号和头部账号候选只能来自关键词行业采集结果。
5. 当前账号公开内容仍可用于账号现状、用户反馈和内容策略分析。
6. 账号报告 AI 上下文不发送内部 ID、联系方式、Logo、图片素材 URL 或官网 URL。
7. 保留现有脱敏、数量上限、候选白名单、禁止逐字输出评论及原子持久化保证。

## 3. 非目标

- 不重构 MediaSpider 通用的 `creator` 模式或底层事件协议。
- 不修改账号报告最终七个顶层输出块及数据库结构。
- 不修改报告结果中的“头部博主参考”概念。
- 不增加新的前端页面、布局或交互。
- 不改变平台 Cookie、采集并发、采集数量等运行参数。

## 4. 总体方案

采用“账号报告领域语义适配 + 工作流证据分流”的方案。

通用 MediaSpider 继续产生稳定的技术事件。账号报告进度聚合器根据采集模式将事件转换为面向用户的领域文案，避免影响其他爬虫调用方。

工作流分别维护当前账号主页采集结果和行业关键词采集结果。证据归一化层接收两个独立输入，输出结构化的当前账号证据与行业证据。Prompt 明确描述两类证据的用途，不再依赖 AI 根据 `owner_hashes` 自行猜测来源。

## 5. 组件设计

### 5.1 AI 安全上下文

在账号报告领域新增专用的 AI 上下文构造函数，只允许以下账号字段：

- `name`
- `description`
- `purpose`
- `type`
- `industry`
- `productService`
- `targetCity`
- `targetAudience`
- `conversionGoal`
- `platforms`

知识库只允许产品名、产品介绍、品牌故事和价格。不得进入 prompt 的字段包括：

- 账号 `id`
- `userId`
- 联系方式
- Logo URL
- 图片素材 URL
- 官网 URL
- 账号主页 URL
- Cookie、请求头、Token 或底层异常

持久化仍使用工作流内部的账号 ID，但 AI 上下文与持久化上下文必须分离，不能通过修改原始 `account` 字典来实现过滤。

### 5.2 采集结果分流

工作流使用两个独立集合：

- `current_account_results`：仅保存 `crawl_by_creator` 成功结果。
- `industry_results`：仅保存 `crawl_by_keyword` 成功结果。

成功计数和平台失败统计继续覆盖两种采集模式，既有“所有支持平台均失败时任务失败”的判断不变。

### 5.3 证据模型

AI 输入证据调整为两个明确命名的顶层分组：

- `currentAccountEvidence`
  - 当前账号公开资料。
  - 当前账号公开作品，按既有互动分排序并限制最多 20 条。
  - 与这些作品关联的有限、脱敏评论趋势证据。
- `industryEvidence`
  - `hotContents`：行业关键词结果中互动分最高的最多 20 条作品。
  - `similarAccounts`：排除当前账号后的最多 20 个行业账号。
  - `topBloggers`：排除当前账号后的最多 10 个头部行业账号。
  - 与行业作品关联的有限、脱敏评论趋势证据。

评论仍遵循每条内容最多 3 条、每个平台最多 10 条、整个报告 prompt 最多 20 条的总上限。总上限在两组证据之间共享，先保留当前账号反馈，再以剩余额度加入行业评论，确保 prompt 大小有界。所有评论继续移除 URL、邮箱、身份证、电话、联系方式、账号提及和凭证，并截断到 200 字。

当前账号作者哈希仅作为归属校验和防混入依据，不作为单独业务结论展示。

### 5.4 AI prompt 约束

Prompt 明确要求：

- `currentAccountEvidence` 只用于判断当前账号现状、已有内容特征、受众反馈和改进机会。
- `industryEvidence` 用于生成行业热门内容、相似账号、头部博主及对标结论。
- `hotContents`、`similarAccounts`、`topBloggers` 的输出候选必须来自 `industryEvidence`。
- 两类评论只可用于聚合趋势、需求和顾虑推断，禁止逐字引用或输出评论者身份。
- 样本不足时必须明确说明，不得用当前账号内容填充行业候选。

AI 输出后的候选白名单过滤继续保留，并仅依据行业证据建立 `hotContents`、`similarAccounts` 和 `topBloggers` 白名单。热门内容也增加内容 ID 白名单过滤，避免 AI 输出当前账号作品或编造行业作品。

### 5.5 进度公开语义

账号报告进度聚合器按模式输出：

| 场景 | 公开文案 |
| --- | --- |
| 进入主页采集阶段 | 采集当前账号主页公开信息 |
| 开始主页采集 | 开始采集当前账号主页公开信息 |
| 发现主页公开资料 | 读取账号公开资料 |
| 主页无效 notice | 当前账号主页链接无效，已跳过主页公开信息采集 |
| 进入关键词阶段 | 采集行业公开内容 |
| 开始关键词采集 | 开始采集行业关键词内容 |
| 发现关键词结果作者 | 发现行业公开账号 |

前端平台摘要数量标签由“博主”改为“账号”。报告结果区域中的“头部博主参考”保持不变。

## 6. 数据流

1. 读取账号档案、账号主页链接和知识库。
2. 使用账号报告专用的 AI 安全上下文规划 3–5 个行业关键词。
3. 按平台采集当前账号主页，结果写入 `current_account_results`。
4. 按平台和关键词采集行业公开内容，结果写入 `industry_results`。
5. 分别归一化两组结果，执行去重、脱敏、排名和总量截断。
6. 将 `accountContext`、`currentAccountEvidence`、`industryEvidence` 和 `sourceMeta` 交给 AI。
7. 严格解析 JSON，拒绝逐字评论，按行业证据白名单过滤内容和账号候选。
8. 原子替换最新版账号报告。

## 7. 错误处理与兼容性

- 当前账号主页无效仍是非阻断 notice；如果关键词采集成功，报告可继续生成。
- 某个平台采集失败仍保留其他平台证据和失败摘要。
- 所有支持平台均无成功采集结果时，工作流继续失败且不覆盖旧报告。
- 旧 workflow 进度快照仍可由前端归一化；新文案不要求数据库迁移。
- 最终报告 API、字段名和旧版五段兼容摘要保持不变。

## 8. 测试策略

### 8.1 后端单元测试

- AI 安全上下文包含允许字段，且不包含 `id`、`userId`、联系方式及素材 URL。
- 当前账号结果只进入 `currentAccountEvidence`。
- 行业结果只进入 `industryEvidence`。
- 当前账号作品不能进入行业 `hotContents` 候选。
- 当前账号不能进入 `similarAccounts` 或 `topBloggers`。
- 评论总量、单内容和单平台上限继续生效，脱敏规则不回退。
- Prompt 明确包含两组证据和用途限制。
- AI 返回当前账号作品或未知内容 ID 时会被白名单过滤。
- 账号报告进度在主页模式和关键词模式产生不同的公开文案。

### 8.2 工作流测试

- 模拟主页与关键词采集同时成功，断言传给 AI 的两组证据来源正确。
- 模拟主页失败、关键词成功，断言报告继续生成且 notice 语义正确。
- 模拟关键词失败、主页成功，断言不会把当前账号作品当作行业热门内容。
- 验证持久化报告结构与现有 API 兼容。

### 8.3 前端测试

- `creator_crawling` 阶段显示“采集当前账号主页公开信息”。
- 关键词阶段显示“采集行业公开内容”。
- 平台摘要计数显示“账号”，不显示“博主”。
- 当前账号主页无效 notice 使用新的领域文案。
- 报告结果仍显示“头部博主参考”。

## 9. 验收标准

1. 账号报告首阶段页面不再出现会将当前账号误解为外部博主的文案。
2. AI prompt 能明确区分当前账号证据与行业对标证据。
3. 当前账号作品不会进入行业热门内容输出。
4. 内部 ID、联系方式、Logo、图片素材 URL、官网 URL 和主页 URL 不进入账号报告 AI prompt。
5. 现有报告输出结构、API 和持久化方式保持兼容。
6. 后端使用 `starx` conda 环境运行相关测试，前端相关测试全部通过。
