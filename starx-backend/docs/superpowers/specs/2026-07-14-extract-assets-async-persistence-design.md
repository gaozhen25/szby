# 链接解析资源异步持久化设计

## 背景

当前链接解析链路会在解析阶段立即下载第三方图片和视频，并上传到项目自有 OSS。用户即使只预览解析结果、没有保存创作，也会产生下载流量、OSS 存储和无业务归属的对象。

本次改造将资源生命周期拆成两个阶段：

1. 解析阶段只获取并展示第三方媒体直链，不下载、不上传 OSS。
2. 用户明确点击“保存进流程管理”或“保存脚本素材”后，业务数据立即保存，后台异步把当前使用的解析记录中的全部图片和视频转存 OSS。

“保存脚本素材”继续保持现有产品语义：同时保存脚本素材和流程任务。

## 目标

- 链接解析接口不产生任何 OSS 写入。
- 保存动作立即返回，不等待图片或视频下载完成。
- 每次保存只处理当前界面正在使用的一条解析记录，不处理同一创作的其他历史记录。
- 当前解析记录中的全部图片和视频都随创作或脚本素材绑定。
- 转存失败后重新解析原始分享链接，使用新媒体直链完整重试一次。
- 第二轮仍失败时保留原始媒体直链，业务保存结果不回滚。
- 重复保存不重复上传相同资源。
- 后端 Python 命令统一使用名为 `starx` 的 conda 环境。

## 非目标

- 不引入 Celery、Redis 队列或新的外部基础设施。
- 不批量迁移历史数据库中已经保存的 OSS 地址或第三方地址。
- 不持久化当前创作未选中的其他解析历史。
- 不改变视频内容分析、图片反推提示词和发布功能的业务逻辑。

## 总体架构

### 1. 解析层

`ExtractReferenceService` 仅调用平台解析器并规范化结果。返回的每个媒体项保留：

- `sourceUrl`：平台解析器返回的第三方媒体地址。
- `url`：解析阶段与 `sourceUrl` 相同，供现有前端统一消费。
- `contentType`：解析器能够确定时填写；不能确定时留空，由后台下载时根据响应头校验。
- `kind`：`image` 或 `video`。
- `storageStatus`：解析阶段为 `external`。

解析接口保存历史后返回 `historyId`。如果历史写入因数据库瞬时故障失败，仍保留现有的“解析结果可返回”行为，此时 `historyId` 为空；用户保存时后端可依据请求携带的当前 `linkReference` 快照补建历史记录。

### 2. 保存编排层

现有页面自动保存与用户显式保存共用 `submit-task`，因此不能在该接口内无条件启动转存。请求增加明确的保存意图：

- 自动保存：不携带资源持久化参数，只更新编辑状态。
- 保存进流程管理：携带当前 `extractHistoryId`、当前 `linkReference` 快照和 `saveScriptMaterial=false`。
- 保存脚本素材：携带相同解析上下文，并设置 `saveScriptMaterial=true`。

显式保存由应用服务在同一个数据库事务中完成：

1. 创建或更新流程任务与创作记录。
2. 在创作资源中绑定当前解析记录的全部原始图片和视频。
3. “保存脚本素材”场景同时创建脚本素材记录，并绑定同一媒体清单。
4. 创建或复用 `asset_persistence` 工作流记录。
5. 在创作、素材和解析历史中写入 `pending` 状态及工作流 ID。

事务提交后才把任务交给后台调度器。接口返回任务、可选素材和持久化任务摘要，前端立即提示“已保存，资源正在后台转存”。

### 3. 资源持久化层

新增独立的资源持久化服务，负责：

- 校验解析历史、创作和账号都属于当前用户。
- 按现有数量、单文件大小和媒体类型限制下载资源。
- 生成稳定的 OSS 对象键并执行幂等上传。
- 记录源 URL 到 OSS URL 的映射。
- 清理单轮失败时已经新建、但尚未被业务记录引用的 OSS 对象。
- 把 URL 映射原子回写到所有相关业务记录。

该逻辑独立于 `db_service.py`，避免数据库服务同时承担网络下载、重试和对象存储职责。

### 4. 后台工作流层

复用项目现有 `WorkflowScheduler` 和 `workflows` 表，新增 `asset_persistence` 工作流类型。该工作流不依赖 AI 服务，因此 `BaseWorkflow` 增加 `requires_ai` 能力标记，调度器只对需要 AI 的工作流检查 Token。

工作流状态与业务展示状态分离：

- 工作流执行正常且全部转存成功：工作流为 `completed`，业务持久化状态为 `completed`。
- 两轮转存均失败并按要求保留源链接：工作流仍为 `completed`，业务持久化状态为 `fallback`，结果中记录失败原因。
- 调度器、数据库或代码异常导致工作流没有完成降级逻辑：工作流为 `failed`，业务状态为 `failed`，保留原始链接。

## 数据模型

### 解析响应与历史

解析响应新增：

- `historyId: str | null`
- 媒体项新增 `storageStatus: external | persisted`

`extract_histories` 新增：

- `persistence_status`：`external`、`pending`、`completed`、`fallback` 或 `failed`。
- `persistence_job_id`：关联的 `asset_persistence` 工作流 ID。
- `persistence_error`：最终失败或降级原因。
- `persisted_at`：成功完成或进入降级状态的时间。
- `media_url_map`：源 URL 到最终 URL 的映射；降级时最终 URL 等于源 URL。

### 创作状态

`creationState.assetPersistence` 保存：

```json
{
  "jobId": "wf_xxx",
  "historyId": "eh_xxx",
  "status": "pending",
  "error": "",
  "updatedAt": "2026-07-14T12:00:00Z"
}
```

`content_creations.assets` 保存当前解析记录的全部媒体项。后台成功后，`assets`、`cover` 和 `creationState.linkReference` 中命中的 URL 一并替换为 OSS URL。

### 素材

`materials` 新增 JSON 字段 `assets`，结构与创作资源一致。脚本素材的 `thumb` 继续用于列表展示，不再承担资源绑定职责。素材返回模型同步增加 `assets` 与持久化状态摘要。

### 工作流

`workflows.input_payload` 保存用户、账号、创作、素材、解析历史等目标标识和保存时的媒体快照；`result_payload` 保存最终状态、URL 映射、重试次数和降级原因。不得在工作流上下文中传递数据库 Session。

## 完整数据流

### 解析

1. 前端提交分享文本。
2. 后端调用平台解析器得到原始分享链接、解析后页面链接及媒体直链。
3. 后端只规范化数据并保存解析历史，不请求媒体文件，不调用 OSS。
4. 前端展示第三方图片和视频，并把 `historyId` 保存在当前 `linkReference`。

### 显式保存

1. 前端只提交当前 `linkReference` 对应的 `historyId` 和快照。
2. 后端验证当前用户对账号和解析历史的权限；`historyId` 为空或历史缺失时，根据快照补建当前历史。
3. 后端立即保存流程任务；保存脚本素材时同时保存素材记录。
4. 后端把全部图片和视频以原始 URL 绑定到创作和素材，并创建 `pending` 工作流。
5. 数据库事务提交后调度后台任务，接口立即返回。

### 后台转存成功

1. 工作流加载自身输入和解析历史，不复用请求 Session。
2. 按媒体顺序下载并校验全部资源。
3. 使用稳定对象键上传 OSS；已经成功持久化的同一资源直接复用。
4. 全部资源成功后，在一个数据库事务中递归替换以下范围内匹配的 URL：
   - 当前解析历史的 `images`、`videos` 和 `cover`。
   - 当前创作的 `assets`、`cover` 和 `creationState.linkReference`。
   - 本次保存创建或关联的脚本素材 `assets`。
   - 同一创作关联的视频分析工作流中的 `video_url`、`cover_url` 和输入媒体清单。
5. 业务状态更新为 `completed`。

### 失败、重新解析与降级

1. 首轮任一资源下载、校验或上传失败，本轮视为失败。
2. 删除本轮新上传且尚未被引用的对象；此前已存在并复用的对象不删除。
3. 使用解析历史中的原始分享文本或 URL 再调用一次平台解析器。
4. 从新解析结果取得全部图片和视频直链，重新执行完整转存。
5. 第二轮全部成功则按正常成功路径回写。
6. 第二轮仍有任一资源失败，则保留保存时绑定的原始媒体地址，状态更新为 `fallback`，记录精简后的失败原因；流程任务和脚本素材保持可用。

## 幂等与并发

- OSS 对象键由账号 ID、解析历史 ID、媒体类型、源 URL 摘要和安全扩展名组成，不直接使用不可信 URL 路径。
- 同一解析历史已有 `pending` 工作流时，重复保存复用该工作流，并把新的创作或素材目标追加到工作流输入。
- 已为该解析历史生成 `completed` URL 映射时，新保存直接应用映射，不再下载。
- 后台回写使用工作流 ID 和当前持久化状态作为条件，旧任务不得覆盖新任务状态。
- 同一源 URL 在一次工作流中只下载和上传一次。

## 安全与资源限制

- 仅接受 HTTP 和 HTTPS 媒体 URL。
- 后台下载复用 `DEFAULT_HEADERS`、超时设置、最大媒体数量和 `max_extract_media_bytes`。
- 图片只接受 JPEG、PNG 和 WebP；视频接受 MP4 和现有支持的 HLS 类型。
- 同时检查 `Content-Length` 和流式实际读取字节数。
- 错误信息不包含鉴权头、Cookie 或媒体响应正文。
- 用户只能持久化自己账号下、自己创建的解析历史。

## 前端交互

- 解析成功后保存接口返回的 `historyId`，切换解析历史时同步切换当前 ID。
- 自动保存不携带持久化意图，确保不会触发 OSS。
- 两个显式保存按钮都携带当前解析上下文；“保存脚本素材”额外声明创建素材。
- 保存成功立即显示“已保存，资源正在后台转存”。
- 重新打开创作或刷新数据后展示：
  - `pending`：资源转存中。
  - `completed`：资源已转存。
  - `fallback`：转存失败，当前使用源链接。
  - `failed`：后台任务异常，当前使用源链接。
- 后台状态不阻塞继续编辑、流程流转或脚本素材查看。

## 测试策略

### 后端单元测试

- 解析阶段返回第三方 URL，断言媒体 Session 和 OSS 均未调用。
- 资源持久化首轮成功，断言所有图片和视频上传且映射正确。
- 首轮失败、重新解析后成功。
- 两轮失败进入 `fallback` 并保留原始 URL。
- 单轮部分成功后失败会清理本轮新对象。
- 已完成解析历史重复保存不重复下载和上传。
- 不需要 AI 的资源工作流不受空 AI Token 影响。

### 后端 API 与数据库测试

- 保存接口立即返回，流程任务和 `pending` 工作流已提交。
- 保存脚本素材同时创建流程任务和带 `assets` 的素材。
- 自动保存不创建资源持久化工作流。
- 只处理请求中的当前解析历史，不处理同创作其他历史。
- 拒绝其他用户的解析历史 ID。
- 后台成功后正确回写解析历史、创作、素材和视频分析工作流。
- 后台降级后业务记录仍存在且使用原始 URL。
- Alembic 升级后新增字段默认值正确。

### 前端测试

- 链接解析结果保存 `historyId`。
- 自动保存请求不携带资源持久化参数。
- 两个显式按钮携带当前历史；保存脚本素材声明同时创建素材。
- 接口返回后立即显示后台转存提示。
- 页面能够展示 `pending`、`completed`、`fallback` 和 `failed` 状态。

### 验证命令

```bash
conda run -n starx pytest tests/test_extract_service.py -v
conda run -n starx pytest tests/test_extract_api.py tests/test_asset_persistence.py tests/test_api_flows.py -v

```

前端使用仓库现有测试命令执行相关单测及完整测试。

## 发布与兼容性

1. 先部署数据库迁移，再部署后端代码，最后部署前端。
2. 新字段都有兼容默认值；旧前端不携带显式持久化意图时不会触发转存。
3. 已有解析历史保持原样，仅在用户再次显式保存并选中该历史时进入新流程。
4. 日志按工作流 ID、解析历史 ID 和创作 ID关联，便于排查转存与降级情况。

## 验收标准

- 只点击“解析链接”时，测试和运行日志均证明没有媒体下载及 OSS 写入。
- 点击任一显式保存按钮后，接口无需等待媒体转存即可返回成功。
- 当前解析记录的全部图片和视频都会绑定到流程；保存脚本素材时也绑定到素材。
- 首轮失败会重新解析原链接并重试一次。
- 第二轮失败时流程与素材仍保存成功，且继续使用原始链接并展示降级状态。
- 同一解析历史重复保存不会产生重复 OSS 对象。
