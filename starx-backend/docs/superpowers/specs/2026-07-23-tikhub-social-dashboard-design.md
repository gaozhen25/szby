# TikHub 社媒数据看板设计

## 目标

账号档案不再要求用户为抖音和小红书填写主页链接，改为配置平台号。数据看板通过 TikHub 将展示号解析为稳定平台身份，读取账号与公开作品数据，并在本地保留每日快照。

本期保留其他平台的主页链接字段，也兼容已有账号的 `accountLinks`，避免旧数据和账号报告流程被破坏。

## 数据链路

1. 账号档案保存 `platformAccounts`，例如 `{ "抖音": "xxx", "小红书": "xxx" }`。
2. 首次打开看板时，抖音号直接调用 TikHub `handler_user_profile_v2`
   的 `unique_id` 参数；小红书号在没有等价直查接口时使用账号搜索，并只接受
   账号号完全匹配的唯一结果。
3. 将 TikHub 的稳定 `userId`、`accountId` 和展示名称缓存到 `platformAccountIdentities`。
4. 后续查询优先使用稳定身份，不重复依赖模糊搜索；平台号变更时仅清除对应平台缓存。
5. 数据看板优先检查账号、平台在北京时间当天是否已经存在成功快照；存在时
   直接从数据库聚合，切换 7/30/90 天不会再次请求 TikHub。
6. 当天尚无快照时才获取账号资料和最近公开作品。抖音额外批量补充作品播放统计。
7. 按账号、平台和北京时间日期保存账号快照及作品快照，再返回聚合后的看板视图。
   修改平台号时清理对应平台旧快照，避免把两个不同账号的数据串联。

## 指标口径

| 看板字段 | 抖音 | 小红书 |
| --- | --- | --- |
| 播放/阅读 | 公开作品播放量 | 接口返回阅读量时展示，否则标记不可用 |
| 互动率 | 点赞、评论、分享、收藏之和 ÷ 播放量 | 点赞、评论、分享、收藏之和 ÷ 阅读量；无阅读量时不可计算 |
| 收藏数 | 作品收藏数汇总 | 笔记收藏数汇总 |
| 涨粉 | 当前粉丝数减周期起点本地快照 | 当前粉丝数减周期起点本地快照 |
| 发布内容表现 | 按作品发布日期汇总播放和互动 | 按笔记发布日期汇总阅读和互动 |
| 内容形式 | 视频、图文、其他占比 | 图文、视频、其他占比 |
| TOP 内容 | 按播放量和互动量排序 | 按阅读量和互动量排序 |

“发布内容表现”表示所选周期内发布作品的当前累计表现，不冒充平台按日新增曲线。涨粉必须等本地快照积累后再展示，不用虚构历史值。

## 模块边界

- `identity.py`：平台号解析和稳定身份缓存。
- `aggregation.py`：纯指标计算，不访问数据库或网络。
- `service.py`：TikHub 调用、快照写入和降级编排。
- `dashboard.py`：接口参数校验和响应组合。
- `DataDashboard.jsx`：平台、周期切换及真实数据展示。

## 降级策略

- 未配置平台号：返回 `unconfigured`，引导用户编辑账号档案。
- 无精确匹配：返回 `unresolved`，不静默绑定相似昵称。
- TikHub 暂时失败：返回 `unavailable`，不使用演示数据填充。
- 某个指标缺少可靠分母：该指标显示不可用，其他已获取字段继续展示。

## 后续扩展
