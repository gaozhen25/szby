# Workflow 中文主要注释设计

## 背景

`app/services/workflow/workflows/` 同时包含具体工作流、工作流基础抽象、AI 子步骤、提示词构建、结果契约以及生成辅助函数。部分文件只有英文概述，部分关键编排阶段缺少职责说明，维护者需要通读实现才能判断各模块在整个工作流体系中的位置。

## 目标

为该目录下全部 Python 模块补充中文主要注释，使维护者能够快速理解：

1. 每个模块在工作流体系中的职责和边界；
2. 每个具体 Workflow 的输入、主要处理链路与输出；
3. 关键编排节点的业务意图，包括上下文加载、AI 子步骤、结果规范化、持久化、进度更新和异常回滚；
4. 共享辅助模块为何存在，以及它们不应承担的职责。

## 范围

覆盖 `app/services/workflow/workflows/` 下的全部 Python 文件：

- 具体工作流：资源持久化、提示词生成、图片生成、脚本改写、选题推荐、视频分析、视频脚本生成和视频脚本改写；
- 基础设施：工作流基类、注册表和 AI 子步骤；
- 支撑模块：生成辅助函数、图片提示词方案、视频脚本提示词、视频脚本输出契约和兼容性导出模块。

## 注释策略

采用分层注释：

1. 每个文件使用中文模块 docstring 概括职责和架构边界；
2. 每个 Workflow 类使用中文 docstring 说明业务作用、处理流程和产出；
3. 在较长的 `execute()` 中使用中文分段注释标识关键阶段，不逐行复述实现；
4. 对包含格式约束、容错、回滚或数据转换规则的辅助函数补充简短 docstring；
5. 将现有英文主要注释统一为中文，但保留协议字段、异常文本和代码标识符原样。

## 约束

- 不修改函数签名、类属性、数据结构、控制流或数据库操作；
- 不修改提示词正文、异常消息、进度阶段名称和对外协议字段；
- 不进行与注释无关的重构；
- 避免无信息量的逐行注释，优先解释模块职责和关键决策原因；
- 注释与实际代码行为保持一致。

## 验证

1. 在项目规定的 `starx` conda 环境中对目标目录执行 Python 编译检查；
2. 检查 Git diff，确认业务代码没有发生语义修改；
3. 搜索目标模块的模块 docstring 和 Workflow 类 docstring，确认覆盖完整；
4. 保留工作树中原有的无关修改，不纳入本次变更。
