# 账号主页无效时保留行业证据设计

## 背景

账号报告依赖平台关键词采集结果生成 `sampleCount`、相似账号、爆款笔记和头部博主。现有实现为了避免把当前账号误判为行业候选，在无法通过账号主页链接确认当前账号稳定 ID 时，会把该平台的全部行业结果排除。

服务器上的真实案例中，账号主页链接为无效值 `wwwww`，关键词采集仍成功获得 48 条内容和 758 条评论，但证据归一化后 `sampleCount` 变为 0，最终三个行业参考模块全部为空。

## 目标

- 账号主页链接缺失或无效时，仍使用成功采集的全部关键词行业结果生成报告。
- `sampleCount` 反映实际进入报告证据的行业内容数量。
- 相似账号、爆款笔记和头部博主继续从行业采集结果中产生候选。
- 账号主页链接有效时，继续通过稳定 creator ID 排除当前账号。
- 保留主页链接无效提示，让用户知道行业候选中可能混入当前账号。

## 非目标

- 不使用账号名称、昵称或 AI 推断当前账号身份。
- 不保证主页无效时完全排除当前账号。
- 不改变行业候选排序、上限、AI 输出结构和前端展示结构。
- 不回填已经生成的历史报告；用户需要重新生成报告。

## 方案

采用“可信 ID 才排除，否则保留全部行业结果”的降级策略。

证据归一化继续接收已确认的 `owner_hashes`。当内容或创作者的 `creator_hash` 命中该集合时，按现有规则排除自身。`unknown_owner_platforms` 不再触发整个平台短路，也不再导致该平台的内容和创作者被全部删除。

工作流仍记录 `creator_url_invalid` notice。该 notice 只表达“无法精确排除当前账号”，不影响关键词采集结果进入报告。

## 数据流

1. 工作流解析账号平台和主页链接。
2. 主页链接有效时，解析稳定 owner ID 并加入 `owner_hashes`；无效时记录提示。
3. 关键词采集结果无论主页是否有效，都进入 `build_report_evidence`。
4. 证据层仅排除明确命中 `owner_hashes` 的内容和创作者。
5. 行业内容完成去重、排序和截断后形成 `hotContents`；同一批内容中的 creator 信息形成 `similarAccounts` 和 `topBloggers`。
6. `sourceMeta.sampleCount` 使用最终行业热门内容候选数量。
7. AI 只能从候选中选择，最终结果继续经过候选白名单过滤和可信链接回填。

## 风险与取舍

主页无效时，关键词结果可能包含当前账号，因此相似账号或头部博主中可能出现自身。这是用户明确接受的降级取舍。相比清空全部行业证据，该方案优先保证报告可用性和样本透明度。

## 测试策略

- 证据单元测试：`unknown_owner_platforms` 包含小红书且 `owner_hashes` 为空时，行业内容、相似账号和头部博主仍然生成。
- 已知 owner 回归测试：存在可信 `owner_hashes` 时，当前账号内容和创作者仍被排除。
- 工作流测试：主页链接无效但关键词采集成功时，持久化报告的 `sampleCount` 大于 0，并保留 AI 从行业证据选择的三个模块。
- 运行账号报告和 MediaSpider 相关测试，确认候选白名单、链接回填与脱敏行为不回归。

## 验收标准

- 无效或缺失主页链接不再导致整个平台行业证据清空。
- 服务器案例等价输入下，48 条采集内容能够产生非零 `sampleCount`。
- 有可信 owner ID 时仍不会把当前账号纳入行业候选。
- 前端和数据库结构无需迁移。
